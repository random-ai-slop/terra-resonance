# Terra Resonance agent entry point

Read `docs/team/WORKFLOW.md` before project work. Coordinated specialists also read the primary local `docs/team/CURRENT.md` at the absolute path supplied in their dispatch; that ignored operational file is not shipped in public clones. Independent contributors follow their own explicit user assignment and can use `docs/team/CURRENT.example.md`. A role charter grants no current write assignment. User instructions take precedence over these project rules.

- The coordinator owns scope, the current task record, cross-domain integration, release acceptance and the complete monorepo and release acceptance; assigned website work can be owned by the website/delivery domain.
- Durable scientific and package/production tasks execute bounded task/attempt assignments, self-check and hand off evidence, then become idle. A role charter alone is read-only.
- Match the current task/attempt, accepted source/contract revision and exact allowed paths before editing. Preserve dirty/untracked work; do not reset or discard it to synchronize.
- Use transient subagents for concrete independent work and adversarial reviews within the coordinator's assigned concurrency allowance. Avoid duplicate implementations and reviews with no distinct risk.
- Use known thread/process handles to establish liveness. An observation timeout is not termination. Return commit, changed paths, executed checks, artifacts and limitations; no claim of completion based only on status text.
- Scientific contracts and physical evidence remain mandatory: no silent mode normalization, unsupported quality promotion or invented reference data. Read `docs/CONTRACT.md` and the relevant numerical evidence before changing conventions.
- Run checks appropriate to changed behavior. Decode/inspect actual scientific outputs when they are affected. Do not repeat unrelated numerical matrices for presentation-only edits.
- All maintained non-website text and owned artifact annotations are English. Website presentation supports English and Simplified Chinese; preserve user-supplied names and metadata.
- Public monorepo worktrees contain `apps/web`. The scientific/package owner uses asset sync `--target package`; web/all writes require the website assignment. Historical pre-publication worktrees lack this folder and must receive the accepted public baseline before website work.
- Canonical public source is `random-ai-slop/terra-resonance`; GitHub Actions publishes Pages and tagged release assets. Do not expand publication destinations, alter global agent settings or start recurring automation as a side effect. Sites publishing uses its preserved local mirror and remains with its assigned owner.

The supported development entry points are described in `docs/DEVELOPMENT.md`. Interpreter and checkout paths are supplied per task; never assume a worktree has the primary `.venv`. Consult the current milestone's acceptance map rather than treating every long-term roadmap item as an active assignment.
