# Implementation contract · release 0.3 / Bundle and Project 1.0 / Scene 1.0–1.1

The scientific baseline completed three planning and three implementation reviews in phase 1. Phase 2 preserves Bundle/Project 1.0 and introduces the separately versioned Scene 1.1 surface-grid contract. Historical reviews retain their at-the-time status; current phase implementation and release evidence are recorded separately. This document defines behavior, not proof that a pending release check has passed.

All packages share these JSON-compatible dictionaries. Python type wrappers are optional; the wire representation is normative. Unknown optional provenance keys are retained. Invalid finite numbers, mode indices and inconsistent lengths fail clearly. All arrays below are ordinary JSON arrays.

## ModeBundle

```ts
type Layer = { id: string; name: string; phase: 'solid'|'fluid'; r_m: number[]; rho_kg_m3: number[]; vp_m_s: number[]; vs_m_s: number[]; q_bulk?: (number|null)[]; q_shear?: (number|null)[] };
type Model = { id: string; name: string; radius_m: number; layers: Layer[]; reference_frequency_hz?:number; provenance?:Record<string,unknown> };
type Region = { layer_id: string; r_m: number[]; u: number[]; v: number[]; w: number[]; potential?: number[] };
type Mode = { id: string; family: 'R'|'S'|'T'; n: number; l: number; frequency_hz: number; q: number|null; regions: Region[]; normalization: string; provenance: Record<string,unknown> };
type ModeBundle = { schema_version: '1.0'; model: Model; modes: Mode[]; provenance: Record<string,unknown> };
```

The adapter converts eigenfunctions to one canonical normalization while preserving the source convention and conversion in provenance; it does not merely change the label. Canonical tangential convention is **unit-normalized vector spherical harmonics**: `u Y er + v gradΩY/k + w er×gradΩY/k`, `k=sqrt(l(l+1))`; gradient terms zero for l=0. Canonical mass normalization is `∫rho*r²*(u²+v²+w²)dr = 1`, label `mass_integral_1`; displacement coefficients then have units kg^(-1/2), not metres. Gravitational potential conversion and common modal scaling are explicitly recorded by adapter. Raw upstream files may be retained as optional provenance artifacts. External bundles must state their convention and be converted before entering the canonical field path; unsupported conventions fail explicitly.

The exported mass normalization uses a documented, layer-wise trapezoidal quadrature over the exported samples, followed by a **single whole-mode rescaling**. Provenance preserves source normalization, source-to-SI conversion, pre-rescale integral and rescale factor. This is a discrete convention, not a claim of exact continuous quadrature. Potential is absent unless actually evaluated; its metadata declares `solved` versus `postprocessed`, units and its consistency with the selected gravity treatment. Zero placeholders are forbidden.

Precisely: for each mode region, linearly interpolate rho from its named model layer onto that region.r_m, integrate rho*r²*(u²+v²+w²) by trapezoidal sum on region.r_m, then sum across regions. Do not use a union of density/eigenfunction grids or extrapolate. Each present region fully spans its named material layer with both endpoints; a missing region means zero support. Zero/nonfinite whole-mode norm is invalid.

Model validation: contiguous layers cover [0,radius_m], within-layer radii strictly increase, arrays have at least two samples, density and vp positive, vs positive in solids and exactly zero in fluids, bulk modulus `rho*(vp²-4*vs²/3)>0`. A density/elastic discontinuity may create adjacent same-phase layers. Materials may have finite positive Q or null=infinite Q; absent arrays mean unspecified, not a default Earth Q. Material-Q frequency correction requires an explicit positive reference frequency and Q arrays for the applicable material components; fluid shear Q must be null. Modal `q` remains separate from material Q.

Required solver provenance includes upstream commit, patch identifiers, model content hash, gravity treatment, requested/actual mesh counts per region, selected frequency interval and any n truncation, matrix dimensions, estimated working memory, runtime, label convention and raw eigenpair identity. Quality includes `status: 'unverified'|'unconverged'|'converged'|'benchmark_checked'`, finite-spectrum counts (negative/near-zero/positive with threshold), `spectral_completeness` for the discrete problem, `mesh_convergence` evidence or null, and warnings. General solve output defaults to unverified; an absence of runtime error is not convergence. Raw n and eigenpair index are retained, including any justified l=1 relabeling. Toroidal identity includes its supporting solid region so inner-core and mantle modes cannot collide.

Fixed locations: `bundle.provenance.groups` is an array of `{family,l,solid_domain_id,status:'success'|'not_applicable',matrix_dimension,spectrum:{negative,near_zero,positive,threshold},spectral_completeness:{status:'complete'|'truncated',reason}}`. `mode.provenance.quality` is `{status:'unverified'|'unconverged'|'converged'|'benchmark_checked',mesh_convergence:null|{coarse_mesh,fine_mesh,relative_frequency_change,tolerance},benchmark:null|{source,reference_frequency_hz,relative_error,tolerance,quantity,model_hash},warnings:string[]}`. The summary does not imply that a frequency benchmark validates eigenfunctions; the two evidence fields remain independent. A requested group failure makes solve raise a structured error and prevents a normal bundle from being saved; no silent partial success. A fluid-only T group is `not_applicable`, not failure. Raw mixed spectra may include constrained/essential subspaces: spectrum counts refer to the raw discrete problem, and each group additionally records excluded_subspace_count, exclusion_basis and thresholds. Extract and justify the physical subspace before square roots. Significant retained negative omega² stops the run; an unclassified raw negative mode causes a physical-subspace extraction error, not an unsupported claim of planetary instability.

Every model layer spans a material region; neighboring regions duplicate the same boundary radius. Interpolate each region independently. Toroidal modes contain only their supporting solid region(s). No matching region means zero field. Interface default is the outer side; callers may select `layer_id` for an explicit side. Points outside the model are zero.

Material layers are not independent vibrational domains: adjacent solid layers belong to one solid domain until a fluid layer separates them. Toroidal modes can span multiple adjacent material layers; solid-domain identity in provenance and mode.id must distinguish otherwise identical n/l labels. Artificially splitting a homogeneous solid layer must not change its spectrum.

For geometric roundoff, snap radial coordinates within `64*Number.EPSILON*radius_m` of a declared boundary to that boundary. Beyond this tolerance an outside point is truly outside. Extreme boundaries closer than twice that tolerance are rejected as unresolved geometry. At poles use analytic limits of angular derivatives and compare Cartesian fields, not ambiguous spherical components. Scalar theta/phi output at a pole uses phi=0 as an explicitly conventional reference. Exact centre is supported by regularity: for S l=1 require v(0)=sqrt(2)*u(0), then with A=sqrt(3/(4*pi)), m=0 gives A*u(0)*ez, m=1 gives -A*u(0)*ex, and m=-1 gives -A*u(0)*ey. Other regular R/T/l>1 centre displacements are zero. Endpoint regularity tolerance is 1e-6*mode_scale; imported nonregular data fail clearly rather than acquiring a directional centre field. Any upstream endpoint correction is explicit adapter provenance and is checked against near-centre limits. This avoids artificial holes in radial section meshes.

## Recomputable analysis inputs

`SolveSpec` is a small JSON object with these explicit keys/defaults: `families:['R','S','T']`, `l_min:0`, `l_max:4`, `frequency_min_hz:0.00005`, `frequency_max_hz:0.003`, `mesh_size:100`, `gravity:2`, `n_max:null`, `linear_q:false`, `target_frequency_hz:null`, `convergence_check:false`, `memory_mib:512`. Unknown keys fail. CLI supports `--config solve.json`; explicit flags override the config and the resolved request is persisted. Validation and solve do not mutate caller-owned input. `convergence_check` is opt-in for general runs; published defaults require it. The secondary mesh is max(2*mesh_size, mesh_size+number_of_regions*4).

Solver provenance contains `request` (the complete resolved SolveSpec) and `effective_settings` (actual mesh allocation, matrix sizes, adaptations). `bundle.model` is always the input reference model. If material dispersion shifts stiffness to target_frequency_hz, store `effective_model` in bundle provenance and its own content hash; otherwise it is identical by explicit reference. For linear-Q frequency post-correction, each mode records elastic_frequency_hz, corrected frequency, correction method, and that the eigenfunction is an elastic approximation at the effective model. Do not pretend one corrected elastic model gives exact eigenfunctions for every mode. No material correction is applied unless linear_q is explicitly enabled. With linear_q=true, target_frequency_hz must be explicitly positive (CLI --target-mhz); missing target is a field error. With linear_q=false, target_frequency_hz must be null.

`ProbeSpec` contains `latitude_deg`, `longitude_deg`, `radius_fraction` (default 1), optional `layer_id`, `start_s`, `step_s`, `sample_count`, `derivative` (0/1/2), and `normalized` (default true). Project may optionally include `probe`; each probe output manifest always includes it. API `export_probe(bundle,scene,probe,path)` supports CSV or SVG/PNG; CSV uses explicit x/y/z axes and normalized/raw units. `normalized=False` applies coefficients to canonical mass-normalized modes without per-mode illustration divisors; these values still are not source-calibrated metres.

API `compare_bundles(a,b,pairs)` accepts explicit pairs of mode IDs and returns a small comparison table plus curve samples. CLI `compare` may suggest a pair from family/l/n and matching solid-domain identity, but requires explicit IDs when ambiguous. No automatic physical mode tracking across model changes is claimed. Plotting uses r/R, each model name/normalization and frequency difference. A comparison is analysis, never a mixed-model SceneSpec.

“Canonical eigenfunction CSV” means the converted u/v/w with kg^(-1/2) labels and layer IDs preserving duplicated boundaries. “Upstream raw file” is only available if explicitly retained; a provenance transformation log is not the raw artifact. Artifact hash proves saved-data identity; re-running a SolveSpec across BLAS/platforms is checked by physical numerical tolerances, not by hash equality or bitwise-identical floating-point output. Quality evidence specifies tested mode IDs, quantity, reference, tolerance and measured error rather than promoting an entire bundle from one tested mode.

## SceneSpec

```ts
type Term = { mode_id: string; m: number; amplitude: number; phase_rad: number };
type MaterialPoint = { latitude_deg:number; longitude_deg:number; radius_fraction:number; layer_id?:string };
type SceneSpec = {
 schema_version:'1.0'|'1.1'; model_id:string; bundle_hash:string; terms:Term[];
 wireframe_spacing_deg?:5|10|15|30|null;
 time_s:number; time_scale:number; deformation:number;
 surface:'solid'|'wireframe'; geography:boolean; color:'radial'|'magnitude'|'theta'|'phi';
 arrows:boolean; reference:boolean; cutaway:boolean; radius_fraction:number;
 quality:'draft'|'standard'|'high'; arrow_scale:number;
 camera:{ azimuth_deg:number; elevation_deg:number; distance:number };
 background:'dark'|'light';
 color_limit:number;
 point:MaterialPoint|null;
 trajectory:{enabled:boolean;start_s:number;duration_s:number;samples:number};
 nodes:boolean;
};
```

`amplitude` is a dimensionless modal illustration coefficient, not an earthquake source excitation. `deformation` is fractional radius per normalized illustration displacement, default 0.035. `time_scale` is physical seconds per playback second, default first-mode period/8. Each spatial mode is divided by ONE time-independent scalar `max over radial samples sqrt(u²+v²+w²)` for illustration. The factor is computed from original eigenfunctions and recorded in exports. No frame-dependent normalization. Color limits default to sum(abs(amplitude)) times a safe angular bound; unchanged with time. Scientific raw eigenfunctions remain unchanged in ModeBundle.

Scene 1.0 accepts absent/null wireframe_spacing_deg and preserves the original input on load/save; a non-null value fails. Scene 1.1 requires the field and accepts null/5/10/15/30. New scenes and six maintained examples use 1.1 with 15 degrees. Only an explicit grid-setting action or new scene construction upgrades a scene; time/camera/locale changes do not. Null means legacy curved-shell triangle edges. Filled cut faces are a documented renderer correction for both versions, not a promise of pixel-identical replay of the old offline all-wire bug. Bundle and Project versions remain 1.0. The website locale never changes scientific content or hashes.

In wireframe mode only, non-null spacing d constructs material parallels at colatitude j*d for j=1..180/d−1 and meridians at longitude k*d for k=0..360/d−1. Each parallel has 2n segments plus a closing endpoint; each meridian has n segments from north to south, with n=max(quality_base,4*(max_l+1)). There is no polar parallel or duplicated 360-degree meridian. Shared pole endpoints are counted. Axis coordinates smaller than 8*float64_epsilon*radius_fraction may be snapped to zero to stabilize strict material-quadrant membership. Clip segments by undeformed midpoint x>0,y<0, retain boundary curves, and never reconnect across the removed quadrant. Curves move at the selected shell radius using the same field, outer-side convention, gain, and absolute time. They are a display grid, not the solver mesh. Filled surfaces neither allocate the grid nor show its sparse-grid notice. For d*max_l>=90, report that extrema between curves may be hidden; keep the requested spacing and suggest smaller spacing or a filled surface. Scientific triangulation and source knots still drive sections, nodes, picking, and color-clipping diagnostics.

`color_limit` is a persisted positive fixed range. Signed scalar colors cover [-limit,+limit], magnitudes [0,limit]. The default is `sum(abs(amplitude_j)*sqrt(3*(2*l_j+1)/(4*pi)))`, floored at 1e-12. The addition theorem bounds each normalized real radial/gradient/curl basis; the factor 3 is deliberately conservative. No frame or Q-envelope rescaling. If sample colors clip, the plot says so. Surface representation, scientific color, and geographic material references are separate layers; geographic coverage is static source-attributed data attached to undeformed material coordinates.

Scene packages use `{format:'terra-project',version:'1.0',bundle:ModeBundle,scene:SceneSpec}`. Standalone SceneSpec requires the matching bundle. The bundle hash is SHA-256 of RFC 8785 JSON Canonicalization Scheme (JCS), using small established implementations for Python and TypeScript instead of maintaining custom number serialization. Model hashes use exactly the entire model object with only its top-level provenance removed; IDs and names are included, so renaming deliberately changes model identity. Bundle hashes cover the entire validated canonical bundle without silently adding defaults. Every subtree, including unknown provenance, must be I-JSON/JCS-compatible: finite IEEE754 numbers, no lone surrogates, no integer outside ±(2^53-1); larger identifiers use strings. Unknown keys are retained. Both implementations share hash fixtures including 1 vs 1.0, small exponents and Unicode. Unknown wire schema versions fail clearly; existing valid state is retained on failed import.

Coordinate: right-handed z north, x lat=0 lon=0, y lat=0 lon=90°E. theta=colatitude, phi=east longitude. Orthonormal complex Y includes Condon–Shortley phase. Real basis m>0 is sqrt(2)*Re(Y_l^m), m<0 sqrt(2)*Im(Y_l^abs(m)), m=0 real Y_l^0. Standing term multiplier is `amplitude*cos(2π f*time_s + phase_rad)*exp(-π f*time_s/q)` (q null means no decay). Same-degree ±m with quadrature phase gives a traveling pattern. Time must be nonnegative for this initial-value decay convention.

Camera is orthographic, targets the origin, z-up, with azimuth from +x toward +y and elevation from the xy plane. `distance` is the visible vertical span in planet radii, default 3.2, not a physical perspective distance. Horizontal span is distance*aspect. Implementations may differ in antialiasing/lighting, never axes, physical field or declared span. Cutaway removes the fixed quadrant x>0,y<0 and draws its bounding radial section faces at x=0,y<=0 and y=0,x>=0; it is independent of camera direction.

Render sampling: latitude interval count is max(base,4*(max_l+1)), longitude count is twice that. base=32/48/96 for draft/standard/high. This affects only display sampling, never solver mesh or data quality. Spatial basis fields are cached then combined at absolute time. Arrow seeds use a deterministic coarser grid and lengths `arrow_scale*radius_m*illustration_vector` (default arrow_scale=0.12), independent of geometry deformation. Both geometry and arrow gains are visible in metadata. Each backend shares two fixed 256-entry RGB palettes distributed as package assets: one zero-centred diverging palette for signed components, one monotonically increasing-luminance sequential palette for magnitude. Color lookup clamps only for appearance and reports clipping.

Geographic mode in v1 means a source-attributed, bundled, low-resolution Natural Earth coastline reference bound to undeformed material latitude/longitude; it is not photorealistic satellite imagery. Both offline and web display the same line data. A wireframe and a geography overlay may be styled differently, but must move with the same material field.

`geography` is independent of solid/wireframe representation, clipped by the same cutaway. It is allowed only at radius_fraction=1; UI disables it for inner shells and exports reject an inconsistent scene instead of projecting surface coastlines into the core. Data source: Natural Earth 1:110m coastline v4.1.0, public domain; distributed with attribution and source checksum.

## Python module ownership and APIs

- `data.py`: `validate_bundle(dict)->dict`, `load_bundle(path)->dict`, `save_bundle(bundle,path)`, `validate_scene(scene,bundle)->dict`, `default_scene(bundle)->dict`, `validate_model(model)->dict`.
- `fields.py`: `real_harmonic(l,m,theta,phi)->(Y,dthetaY,dphiY_over_sin)`; `mode_scale(mode)->float`; `evaluate_field(bundle,terms,points_m,time_s,derivative=0,normalized=True,layer_id=None)->numpy.ndarray[N,3]`; `sample_probe(bundle,scene,lat_deg,lon_deg,radius_fraction,times_s,derivative=0,normalized=True,layer_id=None)->numpy.ndarray[N,3]` in Cartesian axes. Derivatives include Q envelope derivatives.
- `models.py`: `homogeneous_model(radius_m=6371000, rho_kg_m3=5515, vp_m_s=10000, vs_m_s=5500)->dict`; `prem_model()->dict`; model JSON loading through data validation.
- `solver.py`: `solve(model, families=('R','S','T'), l_min=0,l_max=4,frequency_min_hz=0.00005,frequency_max_hz=0.003,mesh_size=100,gravity=2, **options)->ModeBundle`. Solver maintains provenance, checks convergence or reports unresolved quality honestly. Upstream n identity retained.
- `analysis.py`: `compare_bundles(a,b,pairs)` and comparison table/plot export. `export.py` owns `export_probe(bundle,scene,probe,path)` and its CSV/SVG/PNG outputs.
- `export.py`: `export_image(bundle,scene,path,width=1200,height=900)` PNG; `export_video(bundle,scene,path,duration_s=8,fps=None,width=960,height=720)` MP4/GIF using fixed physical sampling; `export_glb(bundle,scene,path,duration_s=8,fps=24)` animated mesh; `export_plot(bundle,path,kind='eigenfunctions',mode_id=None)` SVG/PNG; `export_tables(bundle,output_dir)` CSV; all media write `path + '.json'` manifest containing scene, bundle provenance and hash. Additional arguments allowed without breaking these defaults.

Exports may use Matplotlib for reliable offline scientific rendering; both renderers evaluate the same field contract. Website export PNG/GLB can use its own view; offline high-quality MP4/GIF need not require a browser. Scientific curves, not full textured WebGL, are the SVG contract. GLB stores baked mesh morph displacement and sampled weights, not only a shader.

Solver mesh_size is a target number of elements; every material region receives at least four, with allocation based on physical thickness/travel-time scale rather than number of input samples. Record actual allocation. Interface offsets and fluid-centre/surface boundary conditions require the topology acceptance matrix. A requested frequency range is a filter of the computed discrete spectrum; any n limit/truncation must be explicit, never a hidden fixed n_max. Default memory estimate limit is 512 MiB and can be raised explicitly. Significant negative eigenvalues retained in the justified physical subspace are reported as stability/quality failure, not silently square-rooted into NaNs or mislabelled oscillations; excluded mixed/essential spectrum is counted with justification.

All 3D renderers obey coordinate axes, camera azimuth/elevation, absolute time, display gain, fixed color limits, selected radius and material boundary semantics. `cutaway` means removing the fixed x>0,y<0 quadrant of the sphere and rendering its two true radial section faces, not an empty shell alone. Backend-specific lighting and antialiasing are permitted and identified. Any unavailable appearance is rejected or explicitly listed as omitted before export; it cannot silently become a different view. GLB promises geometry/shape animation with static material, not animated scientific vertex colors, and includes that limitation in the manifest. Blender import script consumes GLB plus project/manifest; `.blend` is only claimed when generated and checked with Blender.

Offline videos use t_k=scene.time_s+k*scene.time_scale/fps for k=0..frame_count-1. duration*fps must be an integer or a validated documented rounding rule applies. The last frame does not duplicate a periodic first frame. GLB may include an endpoint animation key at duration for interpolation. Multi-frequency/Q scenes are not labelled seamless loops. PNG sequence frames and encoded output share times and manifests. Encoder capabilities are checked before lengthy rendering; outputs are written to temporary files then atomically finalized, and failures leave clear diagnostics.

Temporal sampling policy: use `frame_count=floor(duration_s*fps+0.5)` and record actual duration frame_count/fps, requiring at least two frames. For each nonzero term compute frames per apparent period `fps/(frequency_hz*time_scale)`; below 2 fails and below 12 warns. GLB sampled linear weights must meet at least 24 keys per fastest apparent period for small interpolation error, independently of video frame rate; its manifest records actual key spacing and sampled reconstruction tolerance. GIF default is 20 fps and only rates exactly representable as integer 10ms frame delays are accepted (1,2,4,5,10,20,25,50); no silent duration quantization. Browser playback shows an undersampling warning when measured display rate cannot resolve the selected time scale, while keeping absolute-time evaluation.

## Output capability boundary

Encoding and commit details: `export_video(...fps=None)` resolves to GIF20/MP424; an explicitly invalid GIF fps fails rather than being changed. MP4 requires the configured encoder (default libx264) to be available. GIF uses two passes over the PNG sequence (global palette generation, then palette application) rather than buffering a split video branch. Media and manifest are both generated and validated in a temporary sibling directory before final placement. Existing targets are refused unless overwrite=True. Commit failure rolls back the current pair and restores previous valid outputs; never report a file with a missing manifest as success. Frame output directories are committed as one new directory and never mixed with older frames.

GLB linear interpolation acceptance: at least 24 intervals per fastest apparent cycle, including endpoint, then verify key midpoints and arbitrary non-key times. Maximum vertex displacement error must be <=1% of the fixed scene geometric displacement bound `deformation*radius_m*color_default_bound`, not a relative error near an instantaneous zero. Q-envelope curvature is included in actual sampled validation; double key density until passing or reject at key budget. Browser/CLI explains before export that scientific color is frozen at the export start and annotations are carried in manifest. Unsupported decorative/arrow/geographic line animations require explicit export options `omit_arrows` / `omit_geography` (default false), recorded in manifest; if such layers are enabled and cannot be carried, fail before work unless those options are set. This is a normal explicit format choice, not a repeated approval prompt.

## Resource preflight

Default limits are conservative estimates, not OS memory guarantees. Solver working-memory estimate uses `12*8*matrix_dimension²` bytes to cover matrices/eigenvectors/workspaces, compared to memory_mib. Display points include the dense scientific surface (also retained when hidden under wire rendering), section faces, every full indexed curve vertex, arrows, geography and conservative analysis-overlay reserves: max 250,000 points. Base float64 field-cache bytes are `24*geometry_points*terms`; total cache also reserves `24*overlay_points*(terms+1)` for overlay positions and bases, and must stay <=128 MiB. Nodes conservatively reserve two points per possible scientific triangle; a material point adds one, and an enabled trajectory adds its sample count. Clipped unused curve vertices remain counted. Filled surfaces allocate no parametric grid. Cutaway radial nodes are a uniform grid with base/2 intervals plus all material boundary radii (separate sides), so thin layers remain represented. Arrow grid uses 12 latitude intervals and 24 longitude intervals, excluding duplicated poles. Exceeding a limit reports the component and a lower-quality suggestion before allocation, never silently dropping modes.

Media defaults: max width/height4096, max14,400 frames, max2,000,000,000 rendered pixels, estimated temporary disk `4*width*height*frame_count` bytes checked against available space. GLB animated_point_count*target_count <=8,000,000 and estimate `6*12*animated_point_count*target_count+spatial_cache_bytes` <=512 MiB; key array <=1,000,000 scalar weights. Validate estimated budgets before generating fields. An explicit ExportLimits object may raise limits in the offline Python API; there is no CLI ExportLimits flag; the browser has fixed safe limits. Limits constrain combinations, not claims that l=64 with32 terms always fits. They are separate from numerical mesh accuracy.

| Backend | Required retained information | Explicit boundary |
|---|---|---|
| Browser | Full scene appearance, scientific plots, project import/export, PNG, GLB | Numerical solves run in Python; no silent cloud execution |
| Offline PNG/frames/GIF/MP4 | Same field, time, camera, surface/geography, arrows, cutaway, color limits and annotation | Lighting/antialiasing may differ from WebGL; not pixel-identical |
| SVG | Eigenfunction/model/spectrum/probe scientific curves, units, layer markers | Not textured 3D raster disguised as vectors |
| GLB | Baked mesh shape animation, static material, camera and metadata; reference geometry where enabled | Dynamic scalar-color animation and diagram labels are not carried by standard morph animation; declared before export |
| CSV | Canonical eigenfunctions/frequencies/model or explicitly normalized/raw probe series | Not a claimed earthquake seismogram without source excitation |

GLB independent acceptance reconstructs morph vertices at at least three nontrivial times and compares with the field contract. The importer checks buffer bounds, topology, target/weight counts and time mapping. Blender-native verification is a separate conditional step, never replaced by the mere presence of a script.

## Limits

Document and validate a conservative visualization degree limit (initially l<=64), term count (initially <=32), and resource bounds independently of solver capability. Solver can produce higher-degree results that remain useful for data/plots; UI must explain any renderer bound rather than silently dropping modes.

## Explanatory workflow additions

One linked material point is required in the initial release. `point` uses the same coordinates/sidedness as ProbeSpec (whose spatial fields are MaterialPoint); picker results are undeformed Lagrangian material positions, not deformed world-space coordinates. The current marker is drawn at x0+deformation*R*illustration_field(x0,time_s). Trajectory is a fixed physical interval [start_s,start_s+duration_s], sampled inclusively for the path; its current marker still follows the sole scene.time_s. This sampling interval is not a second player. Use exactly `samples` points, at least24 per fastest included cycle and at most2048; reject undersampled/over-budget requests rather than closing or interpolating an invented path. Q and multifrequency paths are not assumed closed. Default point=null, trajectory disabled with start0, duration primary-mode period and samples256; issue presets explicitly enable their linked point.

Single-real-term spatial nodes: `nodes=true` applies to scene.color radial/theta/phi and exactly one nonzero-amplitude term; magnitude and multiple active terms reject with a clear explanation. The contour is the selected spatial eigenfield component, with the temporal factor removed. Advect its material locations with the same scene deformation. Identify identically zero supported regions separately (e.g. T radial) and display 'component identically zero / node contour not applicable', never a dense arbitrary root grid. Do not connect contour segments across material sides or count a discontinuous jump as a root. Radial U/V/W plots mark interior zero crossings per region; endpoint regularity and zero-valued intervals are not ordinary isolated nodes. A selected spherical component at a pole is coordinate-conventional and is not classified as a physical vector node. No multicomponent zero-set classification or permanent multimode nodes are promised.

All web/PNG/video views carry the linked point, trajectory and nodes when enabled. GLB can omit these analysis overlays only with `omit_analysis_overlays=true`, declared before export and recorded alongside existing explicit arrow/geography omission choices. The curve and marker are not silently exported as a different physical quantity. One selected point is required; simultaneous3-point editing is optional future capability, not a delivery gate.

Presentation mode is UI layout state: hides editors, enlarges annotation/legend, retains play/pause, phase fractions, preset switching and Esc. It must not mutate scientific data or SceneSpec. Six problem presets are ordinary true-data projects plus short explanation assets; no script interpreter or tutorial account state is introduced.

## ExportSpec

Optional `project.export` stores a small `{format,width,height,duration_s,fps,transparent,annotation,omit_arrows,omit_geography,omit_analysis_overlays}` object. format is png/svg/csv/frames/gif/mp4/glb; defaults1200×900, duration8 playback seconds, fps=null (container default), transparent=false, annotation=true, omission flags=false. Scientific curve/table kind remains an explicit export operation, not an invented scene clock. Aspect is width/height; remove the previous independent aspect option. ExportSpec does not duplicate scene.time_s, ProbeSpec, solver quality, output paths, overwrite or machine resource budgets. Unknown keys fail; explicit call/CLI options override saved production options, and the fully resolved spec goes into manifest. Existing focused functions remain public; `export_artifact(bundle,scene,path,spec)` may dispatch visual formats without replacing explicit scientific APIs.

Transparency is supported for PNG/SVG, not promised for MP4/GIF/GLB; unsupported transparency requests fail before work. annotation=false removes visual annotations only, never the manifest. CLI examples for GLB with teaching overlays use --omit-analysis-overlays as well as applicable arrow/geography flags. This is an explicit format selection, not a conversational approval step.

Probe CLI maps --duration/--step to a half-open interval [start,start+duration), default start=scene.time_s and explicit --start override. sample_count=ceil(duration/step), times=start+k*step; remove any roundoff endpoint equal to end so every sample is strictly before end. Persist the resolved ProbeSpec, not only command text. GLB aspect defaults to4:3 as an export option and is recorded in manifest.


### Release clarification: numeric JSON and benchmark evidence

Wire integer fields accept finite safe integer-valued JSON numbers (including `1.0`) without mutating caller input or artifact identity. Native solver request APIs may impose stricter Python types. In wire 1.0, benchmark `quantity` is `frequency_hz`; `model_hash` must identify the current canonical model, and `relative_error = abs(f-reference_frequency_hz)/reference_frequency_hz` must agree within `64*eps*max(1,error)`. These checks reject internal contradictions; they do not authenticate a third-party source or turn a frequency check into a full-field validation.

## Installed examples and production precedence (release 0.2)

Public `list_examples() -> list[str]` returns six stable IDs in catalog order. `load_example(id="03-indices") -> dict` loads a fresh, validated self-contained project from installed resources without a source checkout, network, website, or mutable shared return object. `terra example --list` lists IDs; `terra example [id] --out project.terra.json` writes one through the normal no-clobber save path. Unknown IDs fail with available choices. The packaged catalog and website use one source bundle/catalog and preserve canonical teaching metadata. Source-package annotations and maintained teaching material are English; user-authored Unicode is preserved. Website localization does not rewrite scientific metadata or hashes.

`terra scene --wireframe-spacing-deg legacy|5|10|15|30` records the requested setting on a new Scene 1.1. The setting is active only if Scene.surface is wireframe. It does not alter numerical mesh size.

Scientific image CLI precedence is explicit option > the four image options from a fully resolved, present Project ExportSpec > operation defaults (800×500, opaque, annotated) when ExportSpec is absent. A partial saved `{format:"gif"}` therefore contributes default 1200×900 dimensions to an eigenfunction or probe image. Saved fps/duration/omission settings do not apply to these operations; explicit movie-only options are rejected. CSV/tables ignore inherited production options and reject all explicit image flags, including negative boolean flags. Manifests describe actual output dimensions, transparency and annotation settings, not ignored movie settings.

Grid GLB uses essential LINES shell primitives plus filled TRIANGLES section primitives. Both share the same physical bases and time coefficients. Shared attribute/morph accessors may cover the retained scientific mesh as well as curve vertices; all allocated animated vertices count toward morph budgets even if some are unreferenced. When primitives share one mesh weights animation (the Python exporter), count its weights once; when patches have separate animation tracks (the browser exporter), count every track. Independent non-key-time reconstruction checks every animated grid and section vertex. The manifest records requested Scene spacing, effective active spacing, line sampling/point/segment counts, section policy, English annotation locale, and actual resource estimates. Grid density is not an optional GLB omission.

## Toroidal agreement report 1.0

The package-only `earth_modes.agreement` API compares explicitly paired elastic T modes of the same degree and the same complete connected solid support in an identical canonical model. The existing `analysis.compare_bundles` remains a broader raw-curve comparison. Report 1.0 and metric `toroidal-linear-mass-v1` are independent of Bundle/Scene/Project versions. [The frozen Phase-3 contract](PHASE-3.md#revision-2-resolved-contracts-for-final-freeze-review), with its revision-3 corrections, defines exact report/CSV fields, eligibility, loading tolerances and limits; [the user guide](AGREEMENT.md) provides executable commands. The installed `agreement.schema.json` describes structure; `validate_agreement` additionally checks full source hashes, support and recomputed metrics.

For each material side, comparison uses the union of density and both stored radial grids, their linear reconstructions and three-point Gaussian integration of rho*r² products. Continuous comparison norms do not replace the canonical exported trapezoid convention. One whole-domain sign aligns the candidate; near zero overlap the fixed +1 display sign is marked indeterminate. Distance is integrated from the normalized residual directly. Inputs, labels and quality are unchanged. The common model hash includes IDs/names; renaming alone can conservatively prevent comparison.

A report embeds complete sources once, not hash-only references. Saved JSON is authoritative; figure/CSV sidecars are loadable reports with a separate export_production extension. Recomputed data drives graphics and tables after consistency checks; stored historical computation identity stays intact. Agreement is not continuum accuracy, identical finite-mesh material operators, automatic branch tracking or a solver-promotion criterion. No browser implementation is required for this package analysis format.
